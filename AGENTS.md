# Repository Guidelines

## Project Structure & Module Organization

Alpha Engine is a Python signal engine with a report-first workflow. `run.py` is the CLI and menu entry point. Pipeline commands live in `scripts/pipeline.py`. Core trading logic is in `core/`; market adapters are in `markets/`; strategy implementations are in `strategies/`; backtest and validation logic are in `validation/`; SQLAlchemy models are in `db/`. The viewer lives in `docs/`, with `docs/chart_data.json` generated by `chart-export`. Treat `reports/` as the primary review surface: latest run outputs, run history, and agent context live there.

## Session Start & Agent Workflow

Read these files at the start of every session, in order:

1. `CLAUDE.md`
2. `reports/run_log.md`
3. `reports/agent_context.md`
4. `reports/agent_state.json`
5. The relevant `reports/<market>_*_latest.md`

After any pipeline run, compare the newest `_latest.md` file with the previous version in `reports/history/`. Use `run_log.md` for the narrative and `agent_state.json` for a compact machine-readable checkpoint.

## Build, Test, and Development Commands

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the full loop:

```bash
python run.py th run-all
```

Run individual stages:

```bash
python run.py th regime
python run.py th optimise
python run.py th stability
python run.py th report
python run.py th chart-export
python run.py th serve
```

Run tests with `pytest` or a focused target such as `pytest tests/test_research.py::test_label_regime`. On Windows, prefer `PYTHONIOENCODING=utf-8`.

## Coding Style & Naming Conventions

Use 4-space indentation, `snake_case` for modules/functions/strategy ids, and `PascalCase` for classes. Keep changes narrow and prefer existing patterns over new abstractions. When tuning strategy behavior, change one variable at a time so report deltas stay attributable.

## Testing & Report Expectations

Add `pytest` coverage for logic changes in strategies, indicators, risk, backtest flow, or report generation. For pipeline changes, verify both behavior and artifacts: latest report, `reports/history/` copy, `reports/run_log.md`, and viewer export when applicable.

## Commit & Pull Request Guidelines

Use Conventional Commit subjects such as `feat:`, `refactor:`, and `chore:`. PRs should name the affected market or strategy, list commands run, note DB or generated-file impact, and include screenshots if `docs/index.html` behavior changes.

## Configuration & Safety

Default development storage is `alpha_engine_dev.db`; override with `DATABASE_URL` when needed. Do not commit real credentials or private `.env` files. Keep generated reports if they are the intended output of the change; otherwise avoid unrelated artifact churn.
